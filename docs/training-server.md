# Отдельный сервер обучения

Первый общий CatBoost обучается на CPU. Для переноса и аудита достаточно
2 vCPU / 2 ГБ RAM; для обучения удобный старт — 4 vCPU / 8 ГБ, запас —
8 vCPU / 16 ГБ. Диска 50 ГБ достаточно для первого снимка и производных
таблиц, но будущий размер снимков нужно сверять со свободным местом.

На скриншоте мониторинга 782 снимка, 733 подробно обработанных события,
1250 результатов и 423 связи результатов с событиями. Это разные счётчики:
число пригодных уникальных предматчевых примеров показывает `prepare-training`.
Пробный технический запуск возможен на небольшом наборе; он не доказывает
качество прогнозов на будущих матчах.

CatBoost — алгоритм, который мы обучаем на собственных данных. Установка
пакета создаёт среду обучения; файл своей модели `model.cbm` появляется
после успешного обучения. Генеративная модель, GPU, браузер и сервер `finding`
для этого узла не требуются.

## Установка на новом VPS

Поддерживаются Python 3.12–3.14. Для CatBoost 1.2.10 проверено наличие готовых
Linux x86-64 колёс для Python 3.12 и 3.14 в официальном PyPI. Ubuntu 26.04
можно оставить: скрипт проверит версию Python, поставит готовые колёса и
проверит импорт. На облачном исполнителе установка и настоящий CPU-fit
проверены с Python 3.12; на новом VPS проверка выполняется при установке.

В SSH-сеансе **нового** сервера:

```bash
apt-get update && apt-get install -y git python3-venv ca-certificates
git clone --branch feat/fresh-sports-collector --single-branch \
  https://github.com/nutakoe27-commits/doscbot.git /opt/doscbot-trainer
cd /opt/doscbot-trainer
bash scripts/setup-training.sh
mkdir -p /var/lib/doscbot-trainer/incoming /var/lib/doscbot-trainer/models
```

Создаётся отдельная `.venv-training`, фиксируется CatBoost 1.2.10, проверяются
зависимости и импорт. На новом узле не запускаются сборщик, старое приложение
или его установщики. Нативный архив `source/winline.sqlite3` и база `finding`
для подготовки и обучения не нужны.

## Согласованный снимок на старом VPS

Сначала обновите **старый** сборщик. Остановка нужна для обновления импортируемых
модулей; сам снимок можно создавать при продолжающемся сборе:

```bash
cd /opt/doscbot-collector/app &&
systemctl stop doscbot-collector.service &&
git pull --ff-only origin feat/fresh-sports-collector &&
systemctl start doscbot-collector.service &&
.venv/bin/python -m collector --state-dir /var/lib/doscbot-collector/data \
  training-snapshot --output /var/lib/doscbot-collector/transfers/snapshot-20261113-1
```

Команда SQLite backup API копирует одно согласованное состояние, включая
зафиксированные страницы WAL. Копия переводится в самостоятельный файл,
проверяется `quick_check`, вычисляется SHA-256. Исходная база и её режим
журналирования не меняются. Каталог назначения должен быть новым, находиться
вне `data` и `finding`; чужая база, перенаправления и перезапись отклоняются.
При обычной ошибке незавершённая копия удаляется, исходные данные сохраняются.

Файлы снимка: `dataset.sqlite3`, `SHA256SUMS`, `manifest.json`. `cp` или `scp`
работающей исходной `data/dataset.sqlite3` в обход этой команды не учитывает
возможные данные WAL. Переносите созданный снимок.

## Передача с компьютера пользователя

В локальном Terminal на Mac можно передать снимок через две SSH-сессии.
`scp -3` проводит данные через локальный компьютер; приватные ключи не
копируются между VPS. Подставьте IP своего старого и нового серверов:

```bash
ssh root@NEW_VPS_IP 'test ! -e /var/lib/doscbot-trainer/incoming/snapshot-20261113-1' &&
scp -3 -r root@OLD_VPS_IP:/var/lib/doscbot-collector/transfers/snapshot-20261113-1 \
  root@NEW_VPS_IP:/var/lib/doscbot-trainer/incoming/
```

Перед повторным переносом используйте новый номер снимка, чтобы не смешивать
поколения. Учётные данные вводятся в обычном SSH-сеансе, не в чате.

## Проверка и аудит на новом VPS

```bash
cd /var/lib/doscbot-trainer/incoming/snapshot-20261113-1 &&
sha256sum -c SHA256SUMS &&
cd /opt/doscbot-trainer &&
.venv-training/bin/python -m collector \
  --state-dir /var/lib/doscbot-trainer/incoming/snapshot-20261113-1 prepare-training
```

Сначала изучите этот отчёт. В нём важны уникальные матчи, количество меток
по спортам, причины пропусков и доступные даты. Одиночная ночь наблюдений
не обеспечивает надёжную оценку по времени. Неизвестные best-of, овертаймы,
неподдерживаемые рынки и поздние итоги не получают придуманных меток.
Полные и частичные снимки сохраняются без срока удаления.

## Первый эксперимент после выбора дат

Выберите две реальные границы по отчёту, с результатами, доступными до каждой
границы. Не подменяйте их случайным разбиением строк. Здесь `VALID_FROM` и
`TEST_FROM` — переменные с выбранными ISO-датами с часовым поясом:

```bash
cd /opt/doscbot-trainer
.venv-training/bin/python -m collector \
  --state-dir /var/lib/doscbot-trainer/incoming/snapshot-20261113-1 \
  prepare-training --valid-from "$VALID_FROM" --test-from "$TEST_FROM" \
  --output /var/lib/doscbot-trainer/datasets/experiment-1
.venv-training/bin/python -m collector train-baseline \
  --dataset /var/lib/doscbot-trainer/datasets/experiment-1 \
  --output /var/lib/doscbot-trainer/models/experiment-1 --threads 2
```

До задания дат `structurally_ready: false` ожидаемо. Тренер проверяет завершённый
манифест, контрольные суммы, точную схему признаков, отсутствие пересечения
групп и временных нарушений, обе метки в train и наличие запрошенных спортов
во всех частях. Недостаточная подготовка останавливает fit. Количество снимков
не заменяет количество независимых завершённых матчей.

Тренер использует только `features`, не идентификаторы и текст результата.
Пропуски передаются как NaN, категориальные поля — как строки. Веса вычисляются
только на train, число потоков ограничено явно; GPU не выбирается. Validation
используется для ранней остановки. Test используется только для оценки.

Результат: `model.cbm`, `feature-schema.json`, `metrics.json`,
`feature-importance.tsv`. Выводятся log loss, Brier score, калибровка и сравнение
с нормированными вероятностями из коэффициентов, отдельно по спорту и полноте.
Учитываются и строки участников, и число независимых групп матчей.

Модель маркируется `experimental_baseline`, `validated_for_betting: false`.
Небольшие части и отбор только поддерживаемых нормальных итогов явно отражены
в предупреждениях. Эти показатели не равны оценке доходности и не означают
готовности к реальным ставкам. Новые файлы не перезаписывают существующие
модели, а рабочий сборщик остаётся на старом VPS.
