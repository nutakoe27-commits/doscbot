# Монитор сборщика в терминале

Текущие настройки пяти видов спорта и порядок безопасного сброса описаны в
[multisport-restart.md](multisport-restart.md). В карточке доступны все сохранённые
разделы: `[ ]` переключают раздел, `↑↓` прокручивают текст. Следующее описание
общих вкладок остаётся применимым; футбольная сводка — только один из разделов.

Данные обновляются автоматически, пока работает `doscbot-collector.service`.
При `--interval 300` новый цикл начинается через пять минут **после завершения
предыдущего**: длительность самого сбора добавляется к интервалу.
Линия сохраняется для всех полученных событий; подробные рынки и статистика —
для выбранной порции матчей (по умолчанию пять футбольных событий за цикл,
с чередованием ранее просмотренных). Это периодические снимки, а не непрерывная
трансляция каждого изменения коэффициента.

## Обновление существующего VPS

Новая версия использует Rich для оформления терминала. Установите закреплённые
зависимости в существующую `.venv`:

```bash
sudo systemctl stop doscbot-collector.service
cd /opt/doscbot-collector/app
git pull --ff-only origin feat/fresh-sports-collector
.venv/bin/python -m pip install --requirement requirements.txt
sudo systemctl start doscbot-collector.service
bash scripts/monitor.sh
```

Если установка завершилась ошибкой, сначала устраните её и повторите установку.
Код, данные и процессы `finding` не входят в эту процедуру обновления.
В рабочей базе сборщика добавляются индексы и новые виды наблюдений; накопленные
записи и предматчевые `samples` сохраняются.

Монитор открывайте в отдельной SSH-сессии или окне терминала. Он читает базу
одновременно со службой. **`q` закрывает только интерфейс**, сбор продолжается.
Подойдёт обычный SSH-терминал с `TERM=xterm-256color`. Размер от 112 колонок
показывает обзор с таблицами и боковой панелью; более узкое окно получает
компактную компоновку. Минимальный размер — 62 × 17 символов.

## Запуск

Короткая команда в каталоге приложения:

```bash
bash scripts/monitor.sh
```

Скрипт использует `DOSCBOT_DATA_DIR`, если он задан; иначе выбирает существующую
новую базу `/var/lib/doscbot-collector/data/dataset.sqlite3`, а для локальной
разработки — `.local`. Старую базу исходного проекта он не открывает.

Команда с явным каталогом:

```bash
.venv/bin/python -m collector \
  --state-dir /var/lib/doscbot-collector/data monitor
```

Однократный снимок для журнала или проверки:

```bash
bash scripts/monitor.sh --once --no-color
bash scripts/monitor.sh --once --view results
```

Дополнительно доступны `--refresh 2` (от 0.5 до 60 секунд),
`--timezone Europe/Moscow`, `--no-color` и начальная вкладка
`--view overview|matches|results|coverage|errors`. Часовой пояс меняет только
отображение времени. В потоке без терминала или при `TERM=dumb` автоматически
печатается один снимок. Для полноэкранного режима подключите обычный SSH-терминал.
`NO_COLOR` также поддерживается.

| Клавиша | Действие |
| --- | --- |
| `1`–`5`, `Tab` | Переключить вкладку |
| `↑` / `↓`, `k` / `j` | Выбрать матч или строку |
| `←` / `→`, `PageUp` / `PageDown` | Перейти на страницу |
| `Enter` | Открыть карточку выбранного матча; для результата нужна подтверждённая связь |
| `Esc` | Вернуться к таблице |
| `r` | Обновить данные сразу |
| `p` | Приостановить или продолжить обновление экрана |
| `q`, `Ctrl+C` | Выйти из монитора |

## Что видно на экране

- **Обзор:** число событий последней линии, предматчевых снимков, результатов,
  связанных матчей и сохранённых версий. Таблицы показывают последние подробно
  собранные матчи и последние полученные результаты.
- **Матчи:** дата начала, полученный счёт или ожидание, доступность подробных
  данных. Это список матчей с подробным снимком, а не весь каталог линии.
- **Результаты:** исходный текст счёта и ID события, если связь подтверждена.
  Пустая связь означает, что результат ещё не сопоставлен с собранным событием.
- **Покрытие:** полученные состояния фильтров, периоды и пропущенные блоки.
  Полный цикл сбора и полное покрытие виджета проверяются отдельно.
- **Ошибки:** проблемы источника, запросов результатов и привязки за последние
  20 циклов. Пропуски блоков виджета смотрите во вкладке покрытия.

В карточке матча отображаются шесть сезонных показателей обеих команд,
результат и причины неполного покрытия. Отсутствующие значения показываются
как `—`, реальные нули — как `0`.

Состояние процесса определяется по блокировке сборщика и сигналу активности,
который новая версия записывает раз в пять секунд. Видны этап сбора, прогресс
порции, длительность работы, свежесть линии и отсчёт до следующего цикла.
Для старого процесса без телеметрии выводится соответствующая отметка.
Свежесть данных не подменяется тем, что процесс работает.

Монитор не создаёт базу при её отсутствии и не получает сетевые данные.
Он проверяет принадлежность базы сборщику, использует короткие транзакции
SQLite в режиме чтения, получает только видимые строки и считает новые версии
инкрементально. Основные агрегаты обновляются раз в 15 секунд; таблицы —
с выбранным интервалом. Поэтому некоторые общие счётчики могут отставать
на несколько секунд. Временная блокировка базы вызывает повторное чтение.

## Как приходят результаты

При обычном `--history-days 2` сборщик запрашивает результаты футбола за
доступные последние два дня. Успешный последний день перечитывается не чаще
раза в пять минут, предыдущие дни — раз в час. Таймауты имеют отдельную
повторную очередь и не останавливают следующий предматчевый сбор.

Теперь добавлены запросы за дни **ожидающих подробно собранных матчей
возрастом до семи дней**, если такой день ещё предоставляется каталогом
источника. Ограничение запросов за цикл и очередность сохраняются.
Для уже сопоставленных матчей дополнительный добор старого дня прекращается;
исправления счёта продолжают поступать при обычном перечитывании архива.
При `--history-days 0` получение архива явно выключено.

После импорта результатов сборщик добавляет отдельные наблюдения
`event_outcome`, связывающие результат с ID события. Проверяются спорт,
порядок и точные нормализованные имена участников, разница начала не более
15 минут и совпадение `idRadar`, если оба ID есть. При отсутствии одного ID
допускается единственное точное совпадение остальных полей. Противоречащие ID,
переставленные участники и несколько подходящих результатов не объединяются.
Отчёт `last_run.details.outcomes` показывает число связей, новых версий,
ожидающих и неоднозначных событий.

`score_text` сохраняет формулировку ResultService: дополнительные таймы,
пенальти и правила расчёта рынков автоматически не интерпретируются.
Исправленный счёт добавляет новую версию, повтор того же результата не
создаёт дубликат. Предматчевые снимки не переписываются, а результат не
попадает задним числом во входные признаки обучения.

Первое обновление существующей базы создаст связи также для ранее полученных
результатов. Обещать результат каждого события нельзя: он должен появиться
у источника и пройти проверку идентичности. Пока этого нет, интерфейс показывает
ожидание или отсутствие связи.

## Проверка разработки

```bash
bash scripts/setup.sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
.venv/bin/python -m collector monitor --once --no-color
```

Проверки используют отдельные временные базы. Проверены исправления результатов,
неоднозначные связи, неизменность предматчевых снимков, повторный добор старых
дней, чтение при обновлении базы, вкладки и изменение размера терминала.
Дополнительная проверка в PTY проверяет клавиатуру и восстановление экрана
после выхода. Из облачной среды доступ к живому Winline по-прежнему ограничен;
новый проход реального источника следует проверить на VPS.
