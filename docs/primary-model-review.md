# Одна статистическая модель → основная ИИ сайта (только админка)

Новая `train-statistics` по умолчанию пишет `decision_mode: primary_llm.v1`.
Это один CatBoost 1.2.10 на CPU, обученный с нуля на ВСЕХ пригодных размеченных
строках указанного экспорта, без временного ограничения на последние N матчей.
Две строки одного матча — не два независимых обучающих примера.
Число результатов в мониторинге не равно числу пригодных предматчевых входов.
Проверки предматчевого времени, привязки результата, полноты исхода и наличия
статистики обоих участников остаются. Итог целевого матча — только метка,
он не попадает в признаки. Список 30 признаков не содержит цен и их производных.

После фиксации вероятностей основная ИИ сайта получает их, те же статистические
показатели и коэффициенты из снимка. Используется действующий `QWEN_BASE_URL`,
`QWEN_MODEL`, `QWEN_API_KEY`, а не отдельный API или новая учётная запись.
Она может выбрать home/away или skip, не меняя вероятность CatBoost.
Порогов 55% и 5% нет. Ответ — структурированное решение и выбранные ИИ причины
из фиксированного словаря; это исключает выдуманные новости, травмы и проценты
в свободном тексте. Развёрнутые пользовательские разборы Qwen не меняются.

Это независимые бинарные оценки участников: их сумма может отличаться от 100%.
В остатке нельзя подразумевать ничью. Калибровка на новых матчах пока не доказана.

## Получение свежего экспорта на VPS-1

Используем согласованную резервную копию очистки, а не старый учебный экспорт:

```bash
cd /opt/doscbot-collector/app &&
.venv/bin/python -m collector \
  --state-dir /var/lib/doscbot-collector/compactions/before-20261115T150133-1992502 \
  prepare-training \
  --output /var/lib/doscbot-collector/transfers/statistics-export-20261115-3
```

Копия содержит 2 401 запись samples на время её создания; фактическое число
размеченных и пригодных для статистической модели матчей будет меньше либо равно
числу уникальных входов. Никакие 3 000 матчей не добавляются искусственно.
В полученном экспорте: 2 248 уникальных матчей со снимками, 1 833 с подходящим
горизонтом и 1 124 с подтверждённой меткой. Из них тренер исключит строки без
статистики обоих участников. `time_boundaries_missing` ожидается для режима
обучения на всех данных: это не разрешение называть обучение независимым тестом.
Рабочая база, её очистка и сбор не изменяются. Если этот экспорт уже подготовлен,
повторно команду не запускайте и не удаляйте существующий каталог.

## Перенос и обучение на VPS-2

```bash
cd /opt/doscbot-trainer &&
git pull --ff-only origin feat/fresh-sports-collector &&
mkdir -p /var/lib/doscbot-trainer/datasets &&
test ! -e /var/lib/doscbot-trainer/datasets/statistics-export-20261115-3 &&
scp -r root@89.111.143.45:/var/lib/doscbot-collector/transfers/statistics-export-20261115-3 \
  /var/lib/doscbot-trainer/datasets/
```

После успешного переноса:

```bash
cd /opt/doscbot-trainer &&
.venv-training/bin/python -m collector train-statistics \
  --dataset /var/lib/doscbot-trainer/datasets/statistics-export-20261115-3 \
  --output /var/lib/doscbot-trainer/models/statistics-20261115-3 \
  --decision-mode primary_llm.v1 --threads 2 &&
.venv-training/bin/python -m collector package-statistics \
  --model /var/lib/doscbot-trainer/models/statistics-20261115-3 \
  --output /var/lib/doscbot-trainer/bundles/statistics-20261115-3
```

`metrics.json` покажет `training_events`, `training_rows`, `sports`,
`excluded_insufficient_statistics_events`, `unsupported_sports` и контрольные
суммы. `decision_policy` в новом режиме равен null. Измеренные на обучении
Brier/log loss не являются независимой проверкой.
Старые модели не перезаписываются; новые каталоги обязательны.

## Согласованное переключение

Сначала VPS-1:

```bash
cd /root/matchlab &&
git pull --ff-only origin main &&
systemctl stop prognozich-model-worker.timer prognozich-model-worker.service
```

Затем VPS-2:

```bash
cd /opt/doscbot-trainer &&
bash deploy/participant_model/install-server.sh /var/lib/doscbot-trainer/models/statistics-20261115-3
```

Затем VPS-1:

```bash
test ! -e /var/lib/doscbot-models/statistics-20261115-3 &&
scp -r root@89.111.184.88:/var/lib/doscbot-trainer/bundles/statistics-20261115-3 /var/lib/doscbot-models/ &&
cd /root/matchlab &&
bash deploy/participant_model/activate-statistics-bundle.sh /var/lib/doscbot-models/statistics-20261115-3 &&
systemctl restart matchlab.service
```

Активация сверяет контрольные суммы и модель за существующим SSH-туннелем.
Доступ к сборщику остаётся read-only. Публичные разборы и списания не используют
этот эксперимент. Новые ответы появляются только для новых, не обучающих матчей
со снимками после готовности модели и минимум часом до начала.

## Работа и проверка

- CatBoost вызывается прежним `prognozich-model-worker` и сохраняет вероятности.
- Основная ИИ вызывается сайтом автоматически, когда системная очередь свободна.
  Пользовательский поток не занимается экспериментом. Не создаётся третий поток.
- Запрос основной ИИ должен быть начат и закончен в течение 15 минут после
  фиксации вероятностей, отчёт обработчика — не старше 5 минут. Коэффициенты
  относятся ко времени исходного снимка, могут быть старше и не считаются
  текущей ценой исполнения. На момент принятия ответа до начала остаётся минимум час.
- Максимум две последовательные попытки, до 45 секунд каждая, до 400 токенов
  ответа. Все попытки и доступные данные о токенах сохраняются.
- На один зафиксированный прогноз — одно решение. После перезапуска прерванный
  запрос не превращается в новую попытку задним числом. `error`, `expired`,
  `interrupted`, `missed` не считаются решениями skip или успешными прогнозами.
- Версии, вход, SHA входа, модель основного API и время решения записаны в
  `MATCHLAB_DATA_DIR/participant-model-reviews/`. Доступен только администратору;
  API не возвращает полный вход. GET отчёта никогда не вызывает ИИ.
- После результата отдельно считаются попадания статистической модели и
  принятые основной ИИ решения bet. Ничья для выбранного участника — проигрыш.
  ROI виртуальный, по 1 единице на решение; пропуски и ошибки не выигрыши.
- Результаты берутся из полного списка замороженных матчей, даже если запись
  ушла за последние 100 отображаемых строк. При смене SHA начинается отдельный
  эксперимент; старые файлы сохраняются.

Проверка на VPS-1:

```bash
journalctl -u prognozich-model-worker.service -n 5 --no-pager -o cat
```

В админке появятся «Выбор модели» и «Решение основной ИИ», причины и токены.
Если очередь занята или API не настроен, это не подменяется математическим
решением: будет показано ожидание либо отсутствие предматчевой проверки.

Для воспроизведения старого порогового эксперимента используется явный
`--decision-mode price_gate.v1`. Он сохраняет прежнюю маркировку A/B и не
смешивается с основной ИИ.
