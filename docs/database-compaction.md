# Очистка повторяющихся справочников

`compact-dictionaries` сокращает только копии `sports`, `countries`,
`championships` в собственной `dataset.sqlite3`. Для каждой пары
`kind/entity_id` остаётся последняя запись по ID. Исторические названия этих
справочников после очистки доступны в резервной копии; для подготовки признаков
эта история не используется. Названия внутри снимков матчей не изменяются.

Все `samples`, `widget_json`, `widget_data`, `event`, `event_outcome`, рынки,
результаты, курсоры и журналы запусков сохраняются с прежними ID, содержимым,
контрольными суммами и временем получения. Перед фиксацией удаления проверяется
совпадение хеша содержимого всех защищённых таблиц/записей. Семь модулей подготовки
признаков не меняются: старые модели и предматчевые снимки остаются совместимыми.
Старая база finding и исходный `source/winline.sqlite3` не очищаются.

## Что это даст

В диагностике пользователя почти 490 тысяч записей справочников занимают около
95 МиБ полезных JSON, плюс индексы и страницы SQLite. Итоговую экономию показывает
размер файла после VACUUM. Нельзя обещать сокращение базы 6 ГиБ до сотен мегабайт:
основной объём — статистика виджетов, сырые ответы и обучающие снимки.

После успешного применения в metadata сохраняется `dictionary_retention`.
Новый сборщик больше не пишет неизменившиеся справочники, а при изменении
сохраняет только последнюю их версию. До применения команды режим не активен.
История коэффициентов/матчей/результатов продолжает записываться полностью.

## VPS-1: предварительный расчёт без изменений

```bash
cd /opt/doscbot-collector/app &&
git pull --ff-only origin feat/fresh-sports-collector &&
.venv/bin/python -m collector --state-dir /var/lib/doscbot-collector/data compact-dictionaries
```

Поле `remove_records` — точное число удаляемых записей, `payload_bytes_removed` —
только их JSON, без индексов. Предварительный расчёт ничего не удаляет и не
останавливает службы.

## Применение

```bash
cd /opt/doscbot-collector/app &&
bash scripts/compact-dictionaries.sh
```

Скрипт временно останавливает сборщик и обработчик экспериментальной модели,
делает НОВУЮ согласованную полную копию базы (включая WAL), удаляет старые
справочники, выполняет VACUUM и quick_check. Службы, активные до запуска,
возобновляются и при успешном выполнении, и при ошибке. SQLite-запросы монитора
могут помешать уплотнению; в этом случае вернётся `compacted_vacuum_pending`.
Не удаляйте файлы WAL/SHM вручную.

Резервная копия и отчёт остаются в отдельном каталоге
`/var/lib/doscbot-collector/compactions/before-...` (путь выводится при запуске).
Они занимают дополнительное место: это безопасное уменьшение рабочей базы,
не удаление резервных копий с диска. Старый снимок для обучения также сохраняется.
Команда требует свободного места для копии, временного файла VACUUM и WAL;
при нехватке места откажется ДО удаления.

В отчёте ожидаются `state: compacted`, `vacuum_completed: true`,
`retention_enabled: true`, прежнее число `samples`. Сравните
`database_bytes_before` / `database_bytes_after` — фактическую экономию.
Монитор после операции лучше открыть заново: его счётчики накопительные.

Не восстанавливайте резервную копию поверх работающего сборщика: позднейшие
снимки могли уже поступить. Для отката сначала остановите службы, сохраните
текущее состояние и выполните согласованное восстановление основной базы и WAL.

Точечные тесты проверяют неизменность обучающего экспорта для пяти видов спорта,
сохранность всех остальных записей, откат при несовпадении проверки, блокировку
при работающем сборщике, нехватку места и новый импорт справочников.
