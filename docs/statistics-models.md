# Два режима без коэффициентов на входе CatBoost

**A — статистика.** CatBoost получает только спорт, турнир, порядок участника,
область исхода, полноту захвата и 12 показателей формы/сезона/голов с индикаторами
пропусков. Всего 30 признаков. Коэффициенты, обратные вероятности, маржа,
количество рынков и их индикаторы пропусков исключены. Обучение идёт с нуля.
Нужна подтверждённая форма или сезон с сыгранными матчами у обоих участников.
Если этого нет, вход пропускается; отсутствующее значение не заменяется нулём.

**B — статистика, затем цена.** Использует ТОЧНО те же зафиксированные вероятности.
Выбранный участник определяется на этапе A до чтения цены. Затем фиксированный
экспериментальный фильтр проверяет его коэффициент: вероятность не ниже 55%,
`p × odds − 1 >= 0.05`. Другой участник не выбирается из-за более привлекательной
цены. Равные оценки, недостающая цена или непрохождение порогов дают пропуск.
Это два режима одной статистической модели, чтобы измерять эффект отбора,
а не случайные различия между двумя обучениями. Это не вторая нейросеть,
переоценивающая вероятность после просмотра цены.

Текущие пороги — заранее фиксированные параметры ВИРТУАЛЬНОГО эксперимента,
не подтверждение калибровки или доходности. У каждого сохранённого решения
есть версия политики. При её изменении используется отдельный эксперимент;
старые решения не переписываются. На пользователя/оплаты эти версии не влияют.

## Обучение на VPS-2

Используется существующий проверенный экспорт (отдельно от живой базы),
изолированная `.venv-training`, CatBoost 1.2.10, CPU, два потока. Старые модели
не изменяются. Указывайте НОВЫЕ каталоги для каждой версии:

```bash
cd /opt/doscbot-trainer &&
git pull --ff-only origin feat/fresh-sports-collector &&
.venv-training/bin/python -m collector train-statistics \
  --dataset /var/lib/doscbot-trainer/datasets/all-20261115-1 \
  --output /var/lib/doscbot-trainer/models/statistics-20261115-1 --threads 2 &&
.venv-training/bin/python -m collector package-statistics \
  --model /var/lib/doscbot-trainer/models/statistics-20261115-1 \
  --output /var/lib/doscbot-trainer/bundles/statistics-20261115-1
```

Если экспорт обновлён, явно укажите новый путь. Тренер не запускает сборщик,
не пишет в SQLite и не обращается к старой базе finding. Оригинальный экспорт
может содержать цены и метки для проверки/сравнения: в обучающий Pool поступает
только белый список статистических признаков. Метка не становится признаком.

`metrics.json` содержит фактическое число обучающих матчей, исключения по спорту,
список неподдержанных спортов, хеш контракта, параметры и **только обучение**.
Отдельной проверки на новых играх пока нет. Параметры фиксированы до проверки:
200 деревьев, глубина 4, learning rate 0.05, seed 42; старые деревья не дообучаются.

На переданном экспорте all-20261115-1 пригоден 821 матч (1 642 строки).
У всех 160 размеченных теннисных событий экспорт не содержит извлечённых
показателей формы/сезона; они исключены. Ещё 49 событий других спортов не имеют
подтверждённых показателей обоих участников. Это ограничение нынешнего извлечения,
а не утверждение, что на сайте источника нет теннисной статистики. Для тенниса
сначала нужны проверенные дополнительные признаки и новая версия подготовки.

## Подключение двух режимов в админке

1. На VPS-1 обновите `finding/main` и приостановите эксперимент:

```bash
cd /root/matchlab &&
git pull --ff-only origin main &&
systemctl stop prognozich-model-worker.timer prognozich-model-worker.service
```

2. На VPS-2 после обучения/упаковки переключите loopback-сервис на новую модель.
Токен и туннель сохраняются. Код сервера и установщика теперь есть в doscbot:

```bash
cd /opt/doscbot-trainer &&
bash deploy/participant_model/install-server.sh /var/lib/doscbot-trainer/models/statistics-20261115-1
```

3. На VPS-1 перенесите отдельный пакет и активируйте его:

```bash
scp -r root@89.111.184.88:/var/lib/doscbot-trainer/bundles/statistics-20261115-1 /var/lib/doscbot-models/ &&
cd /root/matchlab &&
bash deploy/participant_model/activate-statistics-bundle.sh /var/lib/doscbot-models/statistics-20261115-1 &&
systemctl restart matchlab.service
journalctl -u prognozich-model-worker.service -n 5 --no-pager -o cat
```

Активация сверяет пакет и SHA модели за SSH-туннелем до смены настроек.
`worker.env` выбирает пакет явно; прежние файлы модели и прогнозы остаются.
Для возврата нужно согласованно вернуть прежнюю модель на VPS-2 и пакет на VPS-1;
один только возврат UI не меняет сервер инференса. Остановка таймера приостанавливает
новые прогнозы и сверку результатов, не затрагивая публичные ответы Qwen.

После активации ждём новых предматчевых снимков ПОСЛЕ готовности новой модели.
Обучающие события и их алиасы не входят в будущую проверку. Горизонт 60 минут,
проверка живого каталога и безопасное сопоставление результатов сохраняются.
Цены берутся из того же сохранённого снимка и отображаются с его временем.
Они не обновляются задним числом; это не цены исполнения реальной ставки.

Админка показывает общий Brier/log loss и калибровку независимых вероятностей;
для A — попадания в выбранного участника; для B — долю отбора, попадания,
ожидающие итоги и виртуальный ROI по 1 единице на решение. Пропуски не считаются
успехами, ожидающие итоги не входят в точность или доходность. Число матчей,
а не две строки каждого участника — размер независимой выборки.

Точечные проверки:

```bash
PYTHONPATH=. .venv-training/bin/python -m unittest discover -s tests -p test_statistics_model.py -v
```
