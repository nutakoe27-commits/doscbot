# Пять видов спорта и повторный старт накопления

Сейчас проект собирает данные; обученной прогнозной модели в нём нет.
Футбол, хоккей, теннис, баскетбол и волейбол требуют отдельных схем признаков
и целевых исходов. Голы, очки, сеты и геймы нельзя объединять в один показатель.
Будущие модели нужно обучать и оценивать отдельно по спорту либо явно разделять
эти задачи внутри общей архитектуры. Наличие сборщика само по себе такую
возможность не подтверждает.

## Что исправлено

- Подробная очередь по умолчанию включает пять указанных видов спорта и
  чередует их. При доступных событиях каждого спорта порция из десяти
  содержит по два события каждого. Основная линия по-прежнему сохраняет весь
  полученный каталог.
- Богатый захват больше не зависит от успеха старой текстовой проекции.
  Сначала читаются основные состояния обзора, отчёта и статистики; затем
  обходятся фильтры реально обнаруженных карточек. Большая первая карточка
  не должна поглощать весь бюджет до вкладки статистики.
- Фиксированные 28 футбольных состояний заменены обнаружением карточек,
  таблиц, заголовков и групп переключателей источника. Поддерживаются
  `aria-pressed` и `aria-selected`; неподтверждённые состояния не угадываются.
  Сначала сохраняются все основные разделы, затем варианты фильтров.
- `widget_data.profile` различает спорт и единицы счёта. Спорт проверяется
  по данным провайдера и ожидаемой категории события; числовые ID разных
  источников не отождествляются. Неизвестные показатели сохраняют исходные
  пути/значения. У тенниса и волейбола не появляются выдуманные футбольные поля.
  Сохраняются также категориальные поля: например, покрытие корта или состав,
  **если они пришли от источника**.
- Предматчевые входы нового формата `doscbot.source-input.v2` содержат
  нормализованные данные виджета, его разделы и их время наблюдения.
  Спорт, идентичность события, предматчевая стадия и отсечение по времени
  проверяются до сохранения. Результаты остаются отдельными наблюдениями.
- В карточке монитора появилась навигация по всем сохранённым разделам.
  Старый экран показывал только шесть футбольных показателей; это скрывало
  часть уже сохранённых данных. Теперь доступны карточки источника со всеми
  полученными вариантами, таблицы, история, поля API и рынки.

Источник может давать разные блоки не только разным видам спорта, но и
разным турнирам и матчам. Отсутствующее значение сохраняется отсутствующим.
Успешный запрос, наличие истории или количество JSON не заменяют проверку
богатой статистики. Присланный аудит уже подтверждает богатые снимки хоккея,
баскетбола и волейбола на VPS. Футбол и теннис ещё требуют подтверждения после
исправлений ниже. Офлайн-тесты проверяют механизм и разделение схем,
а не доступность каждого поля на Winline.

## Обновить VPS без очистки

Выполните в root-сессии существующего VPS:

```bash
systemctl stop doscbot-collector.service
cd /opt/doscbot-collector/app
git pull --ff-only origin feat/fresh-sports-collector
.venv/bin/python -m pip install -r requirements.txt
install -m 644 deploy/doscbot-collector.service /etc/systemd/system/doscbot-collector.service
systemctl daemon-reload
systemctl start doscbot-collector.service
bash scripts/monitor.sh
```

Шаблон службы использует прежние каталоги кода/данных/браузеров, пользователя
`doscbot-collector`, headed Chromium под Xvfb, паузу 300 секунд, порцию десять,
бюджет подробного виджета 120 секунд на событие и до шести запросов архива
за цикл. Обход может увеличить длительность цикла; 300 секунд — пауза после
его завершения. Службы исходного `finding` этой процедурой не меняются.

В мониторе выберите матч → `Enter` → `]` или `→` для следующего раздела,
`[` или `←` для предыдущего. `↑`/`↓` прокручивают длинный раздел,
`PageUp`/`PageDown` — по двенадцать строк; `g` возвращает к началу текста.
`Esc` возвращает к списку, `q` закрывает только монитор.
Для прежних снимков доступны только те разделы, которые тогда были записаны.

## Проверить реальную полноту перед сбросом

После завершения первого нового цикла:

```bash
cd /opt/doscbot-collector/app
.venv/bin/python -m collector --state-dir /var/lib/doscbot-collector/data audit
```

Для каждого из пяти видов спорта отчёт содержит число подробных документов,
состояния старой проекции статистики, число богатых захватов, причины пропусков,
новые предматчевые входы и последний ID матча. `ready_to_reset: true` означает,
что за последние 24 часа для каждого запрошенного спорта получен хотя бы один
подтверждённый богатый захват и предматчевый вход нового формата. Для футбола
также требуется представительный снимок сезонных показателей.

Это контроль работы нового сбора, а не подтверждение пригодности данных для
обучения или наличия всех полей на каждом матче. Если `ready_to_reset: false`,
посмотрите причины: невыбранный/недоступный вид спорта, блокировка провайдера,
лимит времени, неподтверждённый спорт, только история без богатых показателей
или отсутствие входов v2. Для диагностики используйте ID из `latest` и
карточку монитора. Автоматического обхода блокировок и выдуманных значений нет.

### Аудит во время сбора и отсутствующие ссылки

`doscbot.collection-audit.v2` дополнительно показывает:

- `collector`: текущий этап, событие, сигнал активности и блокировку писателя;
- `last_run`: завершён ли последний цикл и какие ошибки он сохранил;
- `link_statuses`: найденные/отсутствующие/неоднозначные ссылки за период;
- `current_session`: документы и ссылки только после запуска текущей службы;
- `latest_attempt`: матч, турнир, публичный URL, этап, состояние и причина
  последней попытки, включая ошибки до сохранения рынков.
- `latest.view_state`, `view_failures`, `incomplete_filter_groups`: состояние
  обхода, число пропусков по причинам и ожидаемые/сохранённые варианты карточек.

`in_progress` означает незавершённый сбор, а не отсутствие данных у провайдера.
`statistics_link_missing` означает, что ссылка не обнаружена у конкретного
события. Это не доказательство отсутствия статистики у всего вида спорта.
`ambiguous` не разрешается выбором произвольного ID. Если ссылка не была
в первоначальном снимке, сборщик до шести секунд ждёт появления элемента
статистики в области текущего события, затем использует обычный обработчик
ссылки/кнопки. Номер статистики не вычисляется из номера события или `idRadar`.

Завершённые попытки дополнительно записываются как `event_diagnostic`, поэтому
ошибка этапа больше не пропадает после перехода к следующему матчу. Для старых
записей аудит использует сохранённые рынки и журнал завершённых циклов;
неизвестное состояние остаётся `not_confirmed`.

В присланном пользователем первом живом аудите баскетбол уже имел один
подтверждённый захват: событие `17124248`, статистика `72704674`, 25 разделов,
32 документа и один вход v2. У двух выбранных событий тенниса и двух хоккея
ссылки отсутствовали. У волейбола одно событие было без ссылки, а следующее
`17143419` имело наблюдённую ссылку на статистику `76707074`.
Ссылки футбола также были найдены; первый аудит мог предшествовать окончанию
их сбора. Это отдельные наблюдения, а не подтверждение всей новой версии
на всех пяти видах спорта.

В следующем аудите от 12 ноября 2026, 11:24 МСК, подтверждены также хоккей
`17140906` / `73686902` (30 разделов, 26 документов) и волейбол
`17143420` / `76707070` (13 разделов, 17 документов). У футбола
`17148043` / `69592706` сохранились 39 исходных JSON без ошибок захвата,
но обход был неполным: сезонная статистика 1/6, таблица 1/4, форма 7/12,
забитые/пропущенные 12/24. Текущая версия ищет кнопки внутри обнаруженной
группы, исключает скрытые копии, нормализует пробелы и ждёт загрузки
контролов и aria-подтверждения каждого клика перед следующим переключением.
Равные числовые значения разных подтверждённых фильтров допустимы.
Эти исправления проверены в Chromium с задержками; результат на Winline
проверяется следующим завершённым циклом на VPS.

У выбранных парных матчей тенниса World Tennis не было ссылки статистики,
а исходный `idRadar` равнялся нулю. В очереди подробностей теперь приоритетны
события с ранее найденной ссылкой или положительным `idRadar`, пока ссылка
ещё не проверена. Это только признак вероятной доступности: статистический
URL по этому числу не строится. Уже обновлённое событие на 30 минут
возвращается в обычную ротацию, чтобы дать очередь и остальным матчам.
Ограничение количества подробных событий и равномерная очередь пяти видов
спорта сохраняются; общий каталог событий/линий собирается независимо.

`numeric_projection_truncated_raw_preserved` — предупреждение об ограниченной
поисковой проекции. При сохранённых исходных JSON оно не блокирует квалификацию;
потеря самого сырого захвата блокирует её. `market_documents: 353` — число
версий документов за период, не 353 новых богатых снимка после обновления.
Проверяйте аудит после завершения полного цикла, учитывая `collector.phase`
и `last_run.state`. Условие `ready_to_reset` не ослаблено.

## Очистить только новую базу и начать заново

Предварительный план без изменения данных:

```bash
.venv/bin/python -m collector --state-dir /var/lib/doscbot-collector/data reset-data
```

После положительного аудита:

```bash
systemctl stop doscbot-collector.service
.venv/bin/python -m collector --state-dir /var/lib/doscbot-collector/data reset-data --apply
systemctl start doscbot-collector.service
bash scripts/monitor.sh
```

`--apply` откажется работать без положительного аудита или при активном
писателе. При сбросе **перемещаются в резервную копию** `dataset.sqlite3`
с WAL/SHM и собственный каталог `source`; файлы не удаляются. Копия находится
в `/var/lib/doscbot-collector/data/backups/ДАТА-ID/`, её точный путь выводится
в JSON вместе с манифестом и аудитом. Создаётся пустая база сборщика;
следующий запуск начинает независимое накопление, включая новый исходный архив
и очереди результатов. Прежние экспорты остаются отдельными файлами и обратно
в базу не импортируются.

Проверяются принадлежность базы сборщику, путь собственного исходного архива,
символические ссылки и блокировка писателя. При ошибке инициализации новая
попытка сохраняется отдельно, исходные файлы возвращаются. Владельцы файлов
сохраняются, поэтому служба продолжает писать под прежним пользователем.
Каталог `finding` и его база не входят в операцию.

Применить сброс на VPS из этой облачной сессии нельзя: прямого доступа к серверу
нет. Команда подготовлена и проверена на временных базах, включая WAL и откат;
фактический сброс произойдёт только при её запуске на VPS после аудита.

## Ограничения захвата

На событие: до 120 секунд по умолчанию (`--widget-budget 30..300`),
60 обнаруженных карточек на вкладку, 48 комбинаций одной карточки,
250 снимков и 4 МиБ содержимого представлений. Сырые JSON сохраняются отдельно
с прежними пределами 2 МиБ на ответ, 16 МиБ/200 ответов на событие.
Поисковые проекции ограничены 8000 числовых и 4000 скалярных значений;
ограничение проекции не означает, что исходный JSON был отброшен.
Пропуски/ограничения отражаются в данных и аудите.
